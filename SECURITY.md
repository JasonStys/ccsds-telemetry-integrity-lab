# Security and assurance boundaries

By Jason Stys. This is an educational localhost synthetic packet lab, not flight/ground operational software or a security boundary against the machine owner.

| Boundary               | Controls                                                                                                                                              | Remaining limitation                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Imported data → parser | CLI-only ASCII, whole-byte/record/line caps; explicit endian/size checks; Rust unsafe forbidden; no data execution                                    | Restricted profile, not arbitrary frame/file/secondary-header support                                                                                          |
| Python → worker        | Fixed trusted checkout/bundle path, argument allowlist, no shell, bounded input/output contract and timeout                                           | A compromised executable, repository or OS is already inside the trust boundary; output size is checked after capture, not a sandbox for arbitrary executables |
| Native result → report | Independent Python comparison required for every row; mismatch withholds evidence                                                                     | Agreement is not a formal proof or content/authenticity verification                                                                                           |
| Browser → service      | IPv4 loopback; exact Host; Origin/Fetch Metadata checks; no CORS/uploads/mutations; bounded finite query                                              | Local malware/administrators/extensions and concurrent local resource exhaustion are not prevented; no auth/TLS/public-hosting claim                           |
| Route → files          | Exact built asset allowlist, resolved path/symlink confinement, no source/hidden-file routes                                                          | User-modified build files are trusted local code                                                                                                               |
| Report → UI/export     | Escaped dynamic fields including numeric-contract values, fixed labels/names, inert HTML/CSP, raw input excluded from CSV                             | Full JSON/HTML/input contain explicitly imported text; handle destinations privately                                                                           |
| History → SQL          | Verified content hash, parameters, transaction, deduplication, immutable triggers and cap                                                             | Plain local storage, no encryption or resistance to administrators editing SQL                                                                                 |
| Source → release       | Hashed tool locks, compiler pin, Clippy/forbidden unsafe, native/property/exhaustive tests, CodeQL for supported languages and frozen smoke/checksums | Unsigned binaries, no formal conformance/certification, no universal OS or zero-vulnerability guarantee                                                        |

No radio/spacecraft control, live capture, arbitrary command/remote fetching, accounts, ads, telemetry, analytics, external runtime AI/API/CDN/font or hidden persistence exists. Help/profile links are deliberate user navigation. The service is read-only, but it is not an Internet-grade server or local-client authentication/rate-limiting system. Do not expose it through tunnels/proxies or alter its binding to a public address.

Structural acceptance is not payload integrity, sender identity, replay resistance or physical truth. A plain SHA-256 is not an authenticated signature. Sequence flags are review hints within one source/session, not permanent-loss/replay/maliciousness proofs. The synthetic bit-flip case demonstrates an undetectable content change rather than falsely claiming detection. No application data semantics, time code, CRC/error correction or transfer-frame security layer is validated.

Use synthetic non-sensitive captures. CLI input/history/export are opt-in local files; protect them using OS permissions/encryption/backup and do not commit them. Build-time dependency installation/audits contact their respective services; ordinary app runtime does not. Existing user workflows, caches or account settings are not modified by the application.

For non-sensitive defects use [issues](https://github.com/JasonStys/ccsds-telemetry-integrity-lab/issues) with version, platform and a minimized synthetic reproduction. For a sensitive concern use an appropriate private contact route listed by [Jason Stys](https://github.com/JasonStys); do not assume a public issue is private or that a staffed response SLA exists. Never attach private captures, tokens or operational data. Do not disable checks/protections to bypass a failure.
